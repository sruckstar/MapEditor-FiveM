# `Client/Ui` — форк LemonUI

Здесь лежит та часть [LemonUI 2.2](https://github.com/LemonUIbyLemon/LemonUI) (MIT, Hannele
«Lemon» Ruiz — текст лицензии в `LICENSE.txt`), которой пользуется редактор: меню, элементы
отрисовки и инструкционные кнопки. Пакета `LemonUI.FiveM` в проекте больше нет, DLL рядом со
скриптом не лежит.

## Зачем форк

На FiveM Enhanced C# исполняется на CoreCLR, и каждая скриптовая сборка при загрузке
инструментируется CAS-песочницей (`DouglasDwyer.CasCore`). Политика — «запрещено всё, что не
перечислено», и из `System.Drawing` в ней ровно пять типов:

```
Color   ColorConverter   Point   PointF   PointConverter
```

`Size`, `SizeF`, `Rectangle`, `RectangleF` — нет. LemonUI построена на `SizeF` целиком (135
обращений по IL: размер каждого элемента, `GameScreen.AbsoluteResolution`, сравнения), поэтому на
Enhanced она падала на первом же обращении — `SecurityException` из конструктора `ObjectPool`, ещё
до первого кадра. Правками нашего кода это не лечится: запрещённый тип внутри чужой DLL.

Из рассмотренных вариантов (постпроцесс IL через Cecil, форк, issue в Cfx) выбран форк: он
читается, он под MIT, и он не требует править чужой IL в поставке.

## Что изменено против апстрима

Файлы взяты дословно, с двумя механическими преобразованиями и тремя правками по существу.

Механически:

* ветки `#if FIVEM / #elif RAGEMP / …` свёрнуты до FiveM-ветки — в репозитории один рантайм;
* `LemonUI` → `MapEditor.Ui` в пространствах имён и ссылках.

По существу:

1. **`SizeF.cs` — свой.** Тот же контракт (`Width`, `Height`, `Empty`, `==`), лежит в
   `MapEditor.Ui`. Так как каждый файл слоя объявлен в пространстве имён внутри `MapEditor.Ui`,
   компилятор находит его раньше, чем доходит до `using System.Drawing` в шапке файла, — поэтому в
   перенесённых исходниках не пришлось править ни строки. Вне слоя два `SizeF` неоднозначны, то
   есть ошибка компиляции, а не молчаливый выбор: файлы редактора говорят алиасом, какой им нужен.
2. **`GameScreen.AbsoluteResolution`** больше не читает `CitizenFX.Core.UI.Screen.Resolution` (та
   собирает `System.Drawing.Size` внутри legacy-шима рантайма — именно эта строка и стояла в стеке
   падения), а зовёт `GET_ACTIVE_SCREEN_RESOLUTION` напрямую.
3. **`BaseScaleform`**: убрано устаревшее поле `scaleform`, чей инициализатор просил у игры
   скалеформ с пустым именем при каждом создании набора инструкционных кнопок.

Плюс два выражения в `NativeMenu` переписаны с C# 9 на 7.3 (`is not X` → `!(… is X)`, шаблон
свойств → явные проверки): клиентский проект собирается под `net452`, где нет `System.ValueTuple`,
и версия языка поднята быть не может.

Что **не** переносилось: панели (`NativeColorPanel`, `NativeGridPanel`, `NativeStatsPanel`),
таймербары, остальные скалеформы (`BigMessage`, `Celebration`, `BruteForce`, …), `ScaledAnim`,
`ScaledBink`, слайдеры и устаревшие обёртки (`Screen`, `Extensions/*`). Редактор ими не
пользуется. Абстрактный `NativePanel` остался — на него ссылается `NativeItem`.

## Как проверить, что новых мин нет

```
dotnet build MapEditor.Client.csproj
dotnet run --project tools/sandbox-audit
```

`tools/sandbox-audit` читает политику песочницы прямо из установленного клиента Enhanced
(`CitizenFX.Host.dll`) и сверяет с ней всё, что вызывают собранные сборки. Это тот же вопрос, на
который LemonUI ответила падением на живом сервере, — только заданный до сборки ресурса.

## На Legacy

Ничего не изменилось по поведению: те же нативы, та же раскладка в пространстве 1920×1080, та же
логика меню. `GET_ACTIVE_SCREEN_RESOLUTION` есть в обеих сборках клиента.

## Как тянуть за апстримом

`Client/Ui` — снимок версии 2.2. Механическую половину переноса делает `tools/port_lemonui.py`:

```
py -3 tools/port_lemonui.py <распакованные исходники LemonUI>/LemonUI Client/Ui
```

Он же держит список переносимых файлов. Правки по существу — три штуки выше плюс синтаксис C# 7.3
в `NativeMenu` — скрипт затрёт, их надо наложить заново; `git diff` после прогона показывает ровно
их.
